I. AUDIO STANDARD  Calm Act For CALM ACT Compliancy (United States Broadcast), normal dialogue, not whispered or shouted, must be maintained at -24LKFS as closely as possible. This will ensure that the loudness meets federal regulations, that there is not an issue with an episode’s loudness & consistency in relation to ads and promos, and will make for a good viewer experience. *A tight tolerance surrounding the –24LKFS average is especially critical at the start and end of content or segments to establish smooth program to commercial transitions.  Dialog loudness: -24 LKFS Dynamic limit: -2 dBFS True Peak  Loudness Range: -12 LKFS   EAS Tone The FCC prohibits the transmission of the Emergency Alert System (EAS) codes or Attention Signal (853 Hz) simulation thereof except in the case of an actual emergency. The rule applies to all forms of content, including programs commercials and other paid programming, PSAs, promos and other interstitial material. The FCC has not defined what constitutes a prohibited “simulation” and has brought enforcement actions against sound effects other than actual EAS tones. Content containing EAS tones or simulations will not be accepted for broadcast.  I. AUDIO IDENTIFICATION   Audio should be configured with channel identification. The following audio file and session specifications should be adhered to.  • Regarding Pro Tools sessions, all files must conform to the native framerate and video guide, matching in session length and synchronizing with picture  CREATING INTERLEAVED FILES  Using final Pro Tools Session Print Master material once saved for delivery, please prepare session as follows:  • Ensure that session settings and file start match the guide. • Ensure that all channels are completely consolidated with no edits. • Ensure that channels are configured in the proper channel order. o 5.1 = L, C, R, LS, RS, LFE o 2.0 = LT, RT • If channels are in single mono tracks, create new single 5.1 and stereo tracks and drag audio files in order to the new 5.1 and stereo tracks. • Remove/do not include tail sync pops on any .wav files.   From the prepared session, export interleaved files in accordance with the following: • Select/highlight entire 5.1 and LT/RT track(s). • In the Clips section, click on “Export Clips as Files.” • In the Export Selected pop-up menu, ensure settings: o File Type is WAV o Format is Interleaved o Bit Depth is 24 Bit o Sample Rate is 48kHz • Click Export and check that single files are being created for each channel group (5.1, LT/RT, etc.). • Final audio layout of interleaved file must be:  o 5.1 = L, R, C, LFE, LS, RS  o 2.0 = LT, RT   *If Pro Tools session is set in “film mode” (L, C, R, LS, RS, LFE), when files are exported to an interleaved file, they will be in SMPTE layout (L, R, C, LFE, LS, RS). TEXT/CAPTION COMPONENT GUIDELINES  • Captions must have a period at the end of each segment. If there is no period, captions will remain on-screen    • All closed captioning, subtitle, or forced narrative positioning should not cover actor faces, on-screen graphics, or on-screen text. • Bold, italics, or other stylizations are not recommended for subtitle files (and if included may not appear as intended) • Positional data should be included to ensure subtitle elements do not overlap any on-screen text • Only UTF-8 encoding is accepted • Remember to match framerates • 29.97 content must be Drop Frame • 23.98 and 25 must be Non-Drop Frame • Captions must remain onscreen for a minimum of 10 frames • Time code should be expressed in frames in the HH:MM:SS:FF format (no milliseconds or absolute frame count). • All subtitle deliverables intended to be used to support file fulfillment, shall conform to the IMSC 1.1 spec as defined by the W3C and found here: o https://www.w3.org/TR/ttml-imsc1.1/ • For IMSC1.1  files, timing reference should be set to “MEDIA” to match the time code data track of the video asset to which the component is conformed.  o Please see following section for detailed specs on the creation of IMSC 1.1 Subtitles for HD or UHD deliverables. • Line breaks should be placed according to proper grammatical breaks and natural phrasing • Special characters should all be correctly coded to the specifications of the caption format • Captions should be consistent with audio. If profanity is audible, it should be included in the captions; if profanity or slang have been censored, this should be indicated in the captions. • Sound effects should be captioned when necessary to the understanding of the media • Captions for music should include references to the title and artist whenever possible • Lyrics should be enclosed by musical notes at the beginning and end of each line • Captions sent as SCC files can include up to three lines of text per timecode and can only have 32 characters MAX per line. o Note: If Italics are being used then the MAX characters per line is 31.  Words wither need to be moved to the next row (to have 3 rows on screen instead of 2) or moved down to the next text box.  • Text may be mixed case or upper case, but should remain consistent throughout each episode, with exceptions for emphasis or off-screen narration/dialogue

• Audio Ducking Process: Ducking is typically applied by manual mixing, a console side-chain technique or an automatic microphone mixing device. Mix the audio describer on top of the dual-channel main mono downmix. Apply an appropriate amount of ducking to the dual-channel main mono downmix soundtrack that is triggered by the describer’s modulation.  • Audio Ducking Quality: Ducking should be set in a fashion to emphasize the describer but not diminish the presence and impact of the background sounds. Ducking should not introduce any audible compression artifacts • Dialog Intelligibility: The audio describer typically fits their commentary in between elements of the announcing or dialog of the main dual-channel mono downmix soundtrack. However, there may also be description that occurs at the same time as the dialog or commentary of the main dual-channel mono downmix soundtrack. Ducking should be applied to always create a level of good intelligibility of the describer dialog over the main mono downmix soundtrack • Dynamics: The dual-channel mono composite audio description soundtrack (describer over main dual-channel mono downmix) should be managed for dynamics so good intelligibility and compliant loudness of the soundtrack are established and maintained  • Loudness: Foreground sound (whether the dialog of the describer or the dialog of the dual-channel main mono downmix) is to be provided at -24 LKFS average dialog loudness.
